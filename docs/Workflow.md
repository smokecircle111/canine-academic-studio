# V0.1 工作流

## 1. 准备

- 确认源文件版本、语言、页码范围和版权状态。
- 受版权保护的源文件放在被 `.gitignore` 排除的 `source/` 或仓库外。
- 建立一本书的 Obsidian 笔记并记录书目信息。

## 2. 翻译

- 模型读取翻译 Skill、四份规范和术语 YAML。
- 每次处理可人工复核的小批量内容，建议按小节而非整本书。
- 输出原文定位、译文、图表占位、术语候选和待核问题。

## 3. 复核

- 逐段核对漏译、误译、数字、单位、引文和限定词。
- 对照术语库检查首次出现和后续简称。
- 新术语先标记 `provisional`，审核后再改为 `approved`。

## 4. 回归测试

- 用 `examples/` 中相同输入重新运行 Skill。
- 比较 `expected.md`，重点检查术语、证据强度和结构。
- 若标准答案需改变，必须同时记录规则变化的理由。

## 5. 归档

- 可公开的小样例进入 `examples/`。
- 完整译文进入本地 `output/`，不默认提交。
- 更新 Obsidian 的术语、参考文献、译者注和进度。

## 完成定义

一批译文只有在原文定位完整、术语检查通过、待核项已列出且人工复核完成后，才标记为完成。
